# 把项目规范交给 AI

设计 Markdown 可以指导 AI 实现页面，但它不包含可执行组件。请同时提供对应项目/版本的组件包与实际页面需求。

## 获取正确文件

在项目版本记录中选择已发布版本。“AI 规范数据”和“可执行组件包”是两个独立状态：前者可下载绑定版本的 JSON 数据包和 `DESIGN.md`，后者只在匹配 Runtime 归档就绪时生成。没有匹配代码归档的版本不冒充可执行交付。

AI 数据包的固定读取顺序为 `manifest.json → ai-rules.md → tokens.json → components.json → icons.json → patterns.json → templates.json → layout.json → region-appearance.json`。`templates.json` 中每个模板均使用 `page-template/1` 契约，Schema 见根目录 `template.schema.json`。

- 根目录 `DESIGN.md`：维护设计管理平台本身，包括黑白灰外壳、公共基线和项目预览。
- 项目包中的 `DESIGN.md`：实现该项目的业务页面，只读取该发布快照。
- 快照 `ai-rules.md`：读取入口和约束提示，不是完整组件代码或安装包。
- 本地 `@local/design-system` 候选：含演示流程；正式 `@design-workspace/<project>` 项目包不包含这些演示入口。

## 将 AI 修改稿回流到网站

在项目“版本记录”的当前草稿中选择“导入 AI 修改稿”，可上传 `.md` 或直接粘贴内容。系统会校验 schema、作用域、项目身份、来源版本和快照，再执行三方差异：

`source 冻结版本 → AI 修改稿 → current 当前草稿`

- AI 未改的旧版 Token 会被排除，不回退当前草稿。
- 当前草稿也修改过同一字段时，将其标为“需要确认”且默认不选中。
- 本期只自动反向映射白名单主题 Token。组件、Pattern、布局正文、代码片段和派生 Token 作为评审参考，不直接改代码。
- 应用只修改服务器中的当前草稿，并继续使用 revision 冲突保护。历史版本不变，也不会自动发布。

## 推荐给 AI 的任务说明

> 请先读取附带的 DESIGN.md，确认项目、版本和运行时与组件包一致，然后在现有工程中实现指定页面。
> 使用批准组件、冻结 Token 和包内类型声明。文本输入与选择器的回调接收值，分页容量变化要同时更新数据切片和页码。
> 接入我提供的业务数据、权限和回调，不把演示反馈当成真实保存。不要改用其他组件库，也不要复制管理平台的黑白灰外壳。
> 若缺少组件包、API、图标或业务需求，先列出缺口。完成后报告修改文件、类型/构建检查以及实际浏览器验证结果。

随后补充页面需求、字段、接口、操作权限、空/加载/失败状态。不要只说“照着这个 MD 做个页面”而不提供业务目标。

## 本次修复

1. 新快照原先只有一段笼统 AI 提示，现在包含明确读取顺序、数据/代码边界与缺失处理。
2. 项目交付包原先没有 DESIGN.md，现按冻结数据生成身份、Token、批准清单、完整必填属性与业务回调、状态、布局及可编译示例。
3. API 生成器原先过滤了 onClick、onPageChange、onPageSizeChange、onSortChange 等事件；现在保留项目组件声明的事件与关键点击回调。MD 也保留全部必填属性和业务回调。
4. 根目录规范原先把 danger 混在 variant 中；已明确 variant 与 semantic 的区别，并标出它只适用于管理平台。
5. 旧 v1.5.5 的 ai-rules.md 有把所有输入要求成 DSSelect 等旧规则，历史发布文件不直接改写，不应脱离其具体版本/契约单独套用到当前系统。
6. 排版描述 Token 与可直接用于 CSS 的变量已区别说明，避免把“字号 / 行高 / 字重”字符串直接塞进 font 属性。

## 验证方法与边界

运行 `npm run verify:design-md`：

- 从两个项目、三个版本的隔离快照生成真实组件包和规范。
- 在工程目录之外新建消费工程，npm 安装 tarball；从包内 DESIGN.md 原样提取 TSX 示例。
- 校验项目/版本、包内文档与下载文档的一致性、Token 引用，并执行独立 TypeScript 检查。
- 故意把 DSInput 的值回调改成 event.target.value，确认类型检查确实能识别错误。
- 构建独立消费页面，浏览器检查筛选、分页、容量切换和冻结项目颜色。

这是规范契约与独立消费验证，没有调用外部模型，也没有宣称完成多模型生成成功率评测。它证明文档给出的路径和示例能落地，不保证任何模型在任何提示词下都一次正确。

验收产物位于 `artifacts/design-md-acceptance/`。其中的 8.x 版本和颜色均为测试夹具，不是你的项目新发布版本。实际用户主题、发布记录及旧归档未被替换。

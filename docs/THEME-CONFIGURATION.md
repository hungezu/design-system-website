# 项目主题配置逻辑

更新：2026-09-20。

主题配置是项目空间的主要操作。拥有编辑权限的成员可以从项目概览标题旁的“配置项目主题”进入当前草稿；历史发布版本继续只读。

## 编辑流程

1. 先配置品牌主色、风格预设、信息密度与主题模式。字体、色彩覆盖和尺寸外观按需细调。
2. 右侧使用正式 DS 控件预览组件或完整页面；“对比已保存主题”可以临时查看修改前效果，再返回当前编辑。
3. 修改清单列出变化字段及前后值。保存和撤销位于配置区上方；桌面滚动时保存工具栏保持可见。
4. 保存更新服务器项目草稿，成功后提供“前往版本发布与交付”。保存主题本身不会生成新的发布版本或替换已安装组件包。

## 联动规则

- 品牌主色修改后重新生成辅助、悬停和按下色，包括此前的高级品牌覆盖。界面明确提示这一影响。
- 预设同时应用密度、间距、控件高度、圆角和阴影；实际参数不再匹配预设时显示“已自定义”，不误标为原预设。
- 信息密度同时调整间距与控件高度，仍可在“尺寸外观”单独调整。
- 深浅模式在本次编辑会话中分别保留自定义中性色。服务器仍保存当前模式的主题；这不是同时持久化两套模式的新数据模型。
- 不完整色值、越界字号等输入保留供修正，实时预览使用上一次有效配置，保存和无效 CSS 复制被阻止。

## 保存、撤销与冲突

“撤销本次修改”只恢复当前编辑会话中最近保存的主题，不会发起读取并意外替换为他人的新数据。

保存期间锁定配置控件并防止重复提交。失败保留输入；修订冲突会单独提示，需要明确选择“放弃修改并读取最新主题”后才替换草稿。项目切换后，旧保存请求返回不会覆盖新项目的客户端主题状态。

离开页面、链接跳转和浏览器遍历使用已有的未保存保护；项目/版本切换继续保留全局保护。复制 CSS 和旧浏览器数据载入收纳在“开发取用与旧数据”，不与日常保存混在一起。

## 验证

专项回归覆盖无效颜色保护、密度联动、预设识别、已保存效果对比、深浅模式往返、保存锁定和冲突恢复。完整回归通过 741 项。

浏览器在隔离工作区验证：从项目概览进入编辑、输入无效色值、选择预设、核对中文修改清单、切换前后预览、保存并显示发布入口；窄屏检查未发现根节点横向溢出。未修改用户实际工作区主题。

## 分层尺寸

尺寸外观中新增跟随密度、单项覆盖与恢复跟随机制，详见 [分层尺寸与边距](./THEME-SIZING.md)。旧主题需明确启用后才进入该模式。

# 团队工作区：账号、项目成员与部署

本轮在原 React / React Aria 工程上增加 Node 24 + SQLite 服务。账号、会话、项目、成员、邀请、主题和新发布版本由服务端保存；职业身份与项目权限分开。没有默认超级管理员密码，也没有演示账号切换入口。

## 本机启动与首次初始化

需要 Node.js 24。安装依赖后执行 `npm run dev`，同时启动 5173 前端和 5174 工作区服务。访问 http://127.0.0.1:5173。

首次启动生成 `.workspace/setup-token.txt`。仅部署者可以读取这个文件；在网站“建立你的工作区”中输入初始化码、自选邮箱、姓名及至少 8 位的密码，不限制字符组合。带 * 的字段必填；内容未完整、密码不足 8 位或两次输入不一致时，提交按钮置灰。初始化完成后，该文件会删除，初始化接口永久关闭。不要把初始化码发给团队成员，团队成员通过项目邀请加入。

如果已有单独运行的 Vite，可用 `npm run server` 启动 API。停止旧进程后，推荐统一使用 `npm run dev`。

## 日常流程

1. 平台管理员可从“项目”页右上角点击“新增项目”，填写名称、项目标识和说明，创建后自动进入项目空间。右上角账号菜单的“平台管理 → 项目”继续保留相同创建功能。用户页可检索、停用/启用用户、生成一次性密码重置链接。
2. 进入项目的“成员与权限”，输入邮箱，选择查看者、编辑者或项目管理员，生成邀请链接。
3. 手动将链接交给对应成员。系统不自动发送邮件。链接有效期 7 天，仅显示一次；撤销或重新生成会使旧邀请失效。没有开放注册。
4. 新成员设置自己的账号；已有账号必须输入原密码再加入。职业身份可选择产品经理、设计师、开发或其他，身份本身不授予权限。
5. 编辑者保存主题后，项目成员重新进入/刷新页面可读取最新配置。两位编辑者同时修改时，过期修订会拒绝保存，避免覆盖对方的修改。
6. 项目管理员发布已保存的主题，生成不可覆盖的正式版本；成员可通过带 `version` 的链接取用。

邀请链接只交给收件人，系统没有接入邮箱投递或邮箱验证码。此版本中“受邀邮箱”是由管理员与邀请凭据确认的账户标识，不能宣称已验证邮箱所有权。

## 权限矩阵

| 操作 | 查看者 | 编辑者 | 项目管理员 | 平台管理员 |
|---|---|---|---|---|
| 查看本项目资源、版本 | 是 | 是 | 是 | 所有项目 |
| 保存项目主题 | 否 | 是 | 是 | 所有项目 |
| 发布正式版本 | 否 | 否 | 是 | 所有项目 |
| 邀请、调整、移除项目成员 | 否 | 否 | 是 | 所有项目 |
| 新建项目、停用平台账号、生成重置链接 | 否 | 否 | 否 | 是 |

同一用户可以在不同项目拥有不同权限。平台管理员是独立全局权限，不受项目成员角色降级影响。第一版不提供自定义权限编辑器或平台管理员转让界面。最后一位活动项目管理员不能被降级、移除或停用；新项目创建者初始担任项目管理员。

服务端对每次请求重新核验账号状态和成员关系；移除成员立即阻止其后续项目请求，停用账号使全部会话失效。前端隐藏按钮仅改善体验，不充当权限边界。登录用 12 小时 HttpOnly / SameSite=Strict 会话，数据库只保存令牌散列与 scrypt 密码散列；邀请和重置凭据也只保存散列。变更记录可在成员页查看。

## 现有浏览器数据

旧 localStorage 数据不会删除或自动上传。

- 已保存到旧版浏览器的项目主题，可在该项目主题编辑页选择“载入本机旧主题”，核对后点击“保存主题”再同步到服务器。
- 旧版浏览器发布快照、备份可导出原始记录保留；在管理员版本页的“旧版浏览器数据备份”查看。它们不会自动成为服务器正式版本。
- `public/release-assets` 的已有冻结文件保持不变。运行工作区服务时，读取这些文件也需要相应项目权限；新增版本存在 SQLite 中。
- 内置国科信/客户 B 配置仍是随代码提供的样例；不要将私密客户数据写入前端源码或公开静态目录。新建真实项目的数据由 API 返回。

## 单服务器部署

```sh
npm ci
npm run build
APP_ORIGIN=https://design.example.com WORKSPACE_PORT=5174 npm start
```

`design.example.com` 是占位域名，应替换为实际域名。`npm start` 同时提供 `dist` 前端、API 和受保护的发布资产，默认仅监听 127.0.0.1；由同机反向代理终止 HTTPS 并转发到 5174。反向代理不要直接公开整个 `public/release-assets` 或 SQLite 目录，也不要绕过服务直接托管带项目数据的资源。

`APP_ORIGIN` 必须和浏览器访问的完整来源一致，不带路径或末尾斜杠；启用 HTTPS 来源后，会话 Cookie 带 Secure。生产环境必须使用 HTTPS。需把其他设备直接接入时可显式配置 `WORKSPACE_HOST`，本轮未暴露公网端口、绑定域名或配置服务器。

环境变量：

| 名称 | 默认值 | 用途 |
|---|---|---|
| WORKSPACE_DB | .workspace/workspace.sqlite | 持久化 SQLite 路径，放在持久化磁盘 |
| WORKSPACE_PORT | 5174 | 服务端口 |
| WORKSPACE_HOST | 127.0.0.1 | 监听地址 |
| APP_ORIGIN | 开发环境 http://127.0.0.1:5173 | 唯一批准的站点来源；生产环境设置真实 HTTPS 来源 |

这是单实例 SQLite 部署。进程应由服务管理器保持运行；多副本服务、公司 SSO、邮件网关、MFA、自动备份和云端监控不在本次接入范围。

## 备份与恢复

版本页“备份与恢复”导出当前服务端项目配置、已保存主题和完整冻结版本，采用内容校验、项目管理权限、修订冲突保护和事务恢复。新项目仅平台管理员可恢复；不会导出或修改账号和已有成员。最多 20 MB。详细范围见 [本地取用说明](LOCAL-STABLE.md)。

浏览器“旧版数据备份”仅保留历史本机记录。若需包含账号、成员、审计和全部系统状态的运维备份，请在停止工作区服务后备份完整 `.workspace` 目录（包括 SQLite 主文件和可能存在的 WAL/SHM），并限制备份文件访问。恢复时停止服务，恢复同一组数据库文件，再启动服务；不要用空数据库替换线上数据库来重置密码。正常密码恢复由平台管理员生成 1 小时有效、使用后立即失效的重置链接；接受后旧会话全部失效。

## 验证

```sh
npm run typecheck
npm run typecheck:server
npm test
npm run test:access
npm run lint
npm run build
```

`test:access` 使用隔离临时 SQLite 和真实 HTTP 请求，覆盖首次初始化、会话、跨站写入、角色与项目隔离、邀请撤销/重放/过期、主题保存冲突、发布与取用、最后管理员保护、停用、密码重置及服务重启持久化；备份测试还覆盖动态项目迁移、同号冲突、过期修订、越权、事务中途失败回滚与跨数据库恢复。测试数据完成后清理，不写入实际工作区。

## 管理界面操作样式

成员与权限、平台用户管理的行操作统一使用 AppTextButton：默认透明无描边，文字读取工作台 app-accent（#171717）；禁用时只使用灰色文字，仍不显示底框。移除成员继续保留原确认和服务端权限检查。项目组件预览、表格示例仍读取各自项目主题，不使用这组平台专用动作样式。

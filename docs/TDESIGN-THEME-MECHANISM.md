# TDesign 参数调节机制与本项目融合方案

日期：2026-09-20。参考：https://tdesign.tencent.com/starter/vue/form/base 。结合用户截图与浏览器实际交互，以及当前项目源码核对。

本报告保留机制研究与接入设计。后续第一批尺寸/边距实现已完成，当前使用与验收见 [分层尺寸说明](./THEME-SIZING.md)。下文的其余建议不等于已经实现。

## 实测发现

|机制|实际观察与操作|价值|
|---|---|---|
|保留真实页面作为预览|参数面板打开时，合同表单继续留在主区域；设置集中在侧边|容易发现页面疏密、文字截断和组件间不协调|
|五类参数|色彩、字体、圆角、阴影、尺寸|符合设计师的调整顺序，细项按类展开|
|主参数影响整组规格|字体从“默认”调到“大号”，多个角色同步增加 1px；中正文 14→15px，输入文字实测也是 15px|调的是系统规律，不必逐个改组件|
|阶梯与语义角色分别呈现|字体可切换“阶梯模式 / token 模式”；后者列出 body、title、headline、display、link 等角色|兼顾整体比例与精确应用|
|基础尺寸与组件用途分层|展示 size-1 到 size-16，并按组件大小、上下边距、左右边距、弹出层边距、组件间距分组|能看懂数值在哪里使用|
|允许单项覆盖|comp-paddingTB-m 从 12 调到 13px 后，实测 --td-comp-paddingTB-m 为 13px，基础 --td-size-5 仍为 12px|局部调整不必改动整个基础阶梯|
|组件真实联动|comp-size-m 从 32 调到 33px，合同名称输入框外框实测 32→33px；--td-size-10 仍为 32px|参数表与实际组件建立连接|
|圆角按用途分级|small/default/medium/large/extraLarge/circle 分别解释内部元素、基础控件、弹出层/卡片、对话框等用途|避免一种圆角套用所有组件|
|阴影按场景分级|shadow-1 对应 hover/拖动，shadow-2 对应下拉，shadow-3 对应警示/弹窗|解释调整的用途，而非只展示 CSS 字符串|
|色阶映射可见|色彩面板列出 light、focus、disabled、hover、default、active 对应的色阶|帮助检查主色与交互状态关系|

测试修改的字号、控件高度和边距已改回原值；没有填写或提交合同数据。本轮未验证其导出文件、持久化、撤销栈或全部参数的实现，不根据图标推断这些能力。

一个细节值得改进：单项覆盖后，界面仍显示类似“size-10 : 33px”，而基础 size-10 实际仍是 32px。我们的面板应明确区分“引用值”和“已覆盖值”，避免把它们写成同一个值。

## 当前项目的基础与缺口

现有基础仍是 React 19 / React Aria / 自有 DS。已有项目草稿、模式、主色派生、密度联动、有效配置预览、保存前后对比、修订冲突、冻结版本和前端包交付，可以继续沿用。

当前代码已有 `tvision-color@1.6.0` 色阶能力；这说明本项目不需要为了模仿界面再换一套色彩引擎，不代表本轮核实了参考网站的内部算法版本。

|方向|当前实际情况|需要补的部分|
|尺寸|主题主要覆盖 control-height-md 和 spacing-16；sm/lg 有基线值|形成可见的尺寸阶梯与角色映射，明确哪些层级跟随主参数|
|边距|Button 使用 spacing Token；Select 内边距仍有 9/10px、选项 8/12px 固定值；Dialog 使用 spacing-24|先建立控件内边距、弹层内边距等语义变量并接到控件，再开放调节|
|字体|正文、标题和按钮已有映射；其他角色仍有独立定义|正文/标题/辅助文本/标签/表头等角色的完整字号与行高关系|
|圆角|控件圆角、表格圆角已有设置；容器/弹窗有各自 Token|统一呈现用途层级，保留独立覆盖能力|
|阴影|目前主要是单个 shadow-base 和几个预设|补充浮层/对话框等角色映射；不强制所有控件都使用阴影|
|参数来源|已有 Token 来源和实测检查器|为可编辑参数增加“跟随主参数 / 手动覆盖 / 恢复跟随”状态|
|预览|现有组件与页面预览并列于设置区|扩大场景画布，增加正式 DS 表单、列表、弹窗场景，并显示受影响范围|

对应源码：`src/services/project-theme.ts`、`theme-editor-model.ts`、`src/data/global/color-palettes.ts`、`src/design-system/theme/runtimeThemeAliases.ts`、`src/pages/ThemeEditor.tsx`。

## 建议的使用方式

在现有“配置项目主题”中增加更完整的可视化调节方式：中间是主要工作画布，右侧是可收起参数面板，上方保留保存、对比与场景切换。外层管理导航与账号页面继续使用工作台主题，不随项目试调改变。

参数分三层，但共享同一份项目草稿：

1. **主参数**：品牌色、字体基准、信息密度、圆角程度、阴影强度。先用少量设置形成整体风格。
2. **用途细调**：中号控件高度、输入框左右内边距、弹窗内边距、表格行高、正文行高等。中文名称优先，配尺寸线、盒模型或圆角示意。
3. **变量明细**：按需查看 Token、单位、基础引用、派生规则和最终值；可以筛选“仅看已修改”。不默认铺开全部变量。

预览场景建议提供组件集合、查询列表、业务表单、弹窗/抽屉。复用正式 DS，选中参数时说明影响哪些控件；高亮只属于检查辅助层，不进入组件样式和交付包。

保存、已有主题对比、冲突处理和发布交付继续使用现有机制。TDesign 的浮动按钮外观并非必要；我们已有稳定的工具栏，可保留熟悉的操作位置。

## 最关键的联动规则

采用明确的顺序：**基础参数 → 派生规格 → 项目单项覆盖 → 组件最终取值**。

例如：

- 中号控件高度当前为 32px，显示“跟随密度：舒适”。
- 用户单独改成 34px，标记“已覆盖”，保留推荐值 32px 作对照。
- 后续改为紧凑密度时，仍跟随的项重新计算；这个 34px 覆盖默认保留。
- 点击“恢复跟随”才重新采用派生值，并列入本次变更清单。

这也适用于品牌悬停色、表格圆角等细项，能解决主参数变化时无提示覆盖人工微调的问题。若选择“重置全部细调”，应先展示影响范围。

控件高度、文字行高和上下内边距必须共同校验，避免出现文字装不下的组合；圆形图标按钮、胶囊标签等形状约束也应保留。

## 数据与交付需要同步演进

现有扁平主题字段继续兼容；新增的细项应使用有类型和范围约束的参数注册表，记录默认来源、派生规则、允许覆盖项及关联组件。旧主题迁移时保守保留已保存的实际值，不能猜测其都是可重新生成的默认值。

保存内容要能够同时保留参数输入和最终解析结果。冻结版本还需记录派生规则版本；如果新增快照资产，必须升级快照格式和校验逻辑，不能直接改变旧格式的文件清单。备份恢复、版本差异、检查器、CSS 导出和项目安装包都要覆盖新增参数。

## 实施优先级

**第一批：尺寸与边距。** 先做 sm/md/lg 控件高度、控件横向内边距、弹层内边距和组件间距的实际绑定；这是与用户截图最直接对应、当前缺口也最明显的部分。通过输入框、按钮、选择器和弹窗的 DOM 实测后再开放 UI。

**第二批：调节面板与场景画布。** 在同一编辑器呈现主参数/细项，增加示意图、跟随与覆盖状态、单项恢复和受影响组件说明。保留现有保存与对比流程。

**第三批：字体、圆角和阴影的完整规格。** 按角色形成阶梯，补齐所有消费者和组合状态，再纳入冻结与交付验证。

验收以“参数变化确实作用到组件、保存重载一致、旧版不变、安装包效果一致”为准。面板里不放未接到正式组件的装饰性滑块。

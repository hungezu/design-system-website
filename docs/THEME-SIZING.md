# 分层尺寸与边距

2026-09-20。TDesign 机制融合的第一批实现：13 项尺寸参数、跟随/覆盖状态、正式控件绑定、保存冻结与独立包验证。完整字体阶梯、阴影角色和新的全屏画布仍属于后续阶段。

## 使用

进入项目 → 配置项目主题 → 尺寸外观 → 分层尺寸与边距。

旧主题默认沿用原有尺寸。点击“启用分层调节”后，原来与密度推荐不同的控件尺寸会保留为覆盖值，不静默重设。已启用的主题按三组展示：控件尺寸、控件内边距、浮层与间距。

- 跟随密度：切换紧凑、舒适、宽松时按当前规则更新。
- 已覆盖：单独输入数值后保持该值，切换密度或预设不会移除覆盖。
- 恢复跟随：移除该项覆盖，使用当前密度推荐值。
- 仅看单项覆盖：集中查看人工调整。
- 变量映射：查看控制实际组件的 CSS 变量；每项同时列出影响范围和尺寸示意。

保存、撤销、已保存效果对比、并发冲突提示和版本发布继续使用原流程。保存不会自动发布或替换已安装的版本包。

## 已绑定范围

|用途|参数与实际消费者|
|---|---|
|三档控件高度|小/中/大按钮、输入框、选择器；中号高度映射到分页|
|按钮内边距|小号文字按钮，以及中/大号文字按钮；纯图标按钮保持正方形和零文本内边距|
|输入框内边距|输入框、多行输入框的左右内边距|
|选择器内边距|起始侧、结束侧分别调节，保留旧默认的 10px / 9px|
|下拉选项内边距|上下、左右分别调节|
|弹层内边距|桌面对话框/抽屉内容区，与 600px 以下的窄屏内容区分别调节；不改变外部遮罩留白|
|组合区域间距|主题预览的组件组合和表单区域；不声称修改了所有业务页面布局|

“组件”预览加入三档按钮以及真实 DS 对话框、抽屉入口，可直接检查控件和 Portal 中的实际取值。

## 模型与兼容

新增可选 `sizing: { version: 1, overrides: {...} }`。缺失时保持旧模式；启用时从当前主题及项目基线保留实际尺寸。规则和参数注册表在 `src/services/theme-sizing.ts`，所有覆盖均有白名单、单位和范围约束。

服务端拒绝未知字段、未知规则版本、非数值、越界值、文字装不下的高度，以及小/中/大高度顺序倒置。预览沿用上次有效值，修正前不能保存。

参数输入随 `region-appearance.json` 冻结，实际 CSS 值随 Token 资产冻结；`layout.json` 记录真实解析后的中号高度和组合间距。仍使用已有资产清单，不增加旧格式必需文件。验证器会检查分层输入与对应冻结变量是否一致。

旧冻结版本缺少新字段时走兼容默认，不读取当前草稿覆盖；已发布文件没有回写。新增变量进入 Token 注册表，Button 的专属内边距变量继续归属于组件层。

## 本轮验证

- 单元回归：旧主题迁移、项目基线覆盖保留、密度联动、单项恢复、非法参数拒绝、文字和高度校验、备份往返、冻结输入/变量一致。
- 服务端：通过真实 HTTP 保存、重读、拒绝非法参数、发布与备份。
- 编辑器：输入框覆盖为 20px 后切换宽松密度，覆盖保持；跟随的小/大控件分别变为 32px / 44px。恢复输入框跟随后变成 12px，保存重载仍为 12px。
- 独立 tarball：安装到独立依赖目录并通过类型/构建。浏览器实测中号高度 36px、按钮横向内边距 22px、输入框横向内边距 18px、选择器起始内边距 20px、桌面弹层内容内边距 32px；390px 视口下弹层内容内边距为 16px。

全部浏览器写入只发生在隔离的 `sizing-lab` 项目，没有修改用户实际工作区主题。测试制品在 `artifacts/sizing-acceptance/`，不是用户的正式发布。

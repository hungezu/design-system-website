# 项目组件交付：实现与接入

2026-09-19。本轮实现了从项目已发布快照生成前端包、受项目权限保护的生成与下载，以及独立业务参考工程接入。测试版本均来自隔离数据库，不是用户项目的正式发布。

## 日常使用

1. 项目管理员保存主题并发布版本。
2. 在“版本记录”选择该版本，查看上方“前端接入”。
3. 管理员点击“生成前端组件包”；页面显示后台生成状态，完成后自动出现下载入口。失败可以重试；离开页面不会取消任务。
4. 有项目查看权限的成员下载 `.tgz` 和接入说明，将包放入业务工程，使用页面上的安装命令并提交依赖锁文件。
5. 引入包的 `style.css`，用 `ProjectTheme` 包裹业务区域，使用正式 DS 控件并传入自己的数据、校验、加载状态与回调。

项目包名称为 `@design-workspace/<项目标识>`，包版本对应项目发布版本。当前是本地私有 tarball 分发，未发布到 npm 仓库。支持范围为已验证的 React 19 客户端 Web；Vue、SSR 和其他 React 主版本另行适配验证。

包包含共享正式控件、该项目的冻结变量和快照、TypeScript 声明、接入说明、受控表单示例与第三方许可。`PROJECT_RELEASE` 提供项目版本和代码关联。`ProjectTheme` 自动应用包内冻结变量，DS 浮层继承所属主题。业务运行时不需要连接设计管理平台。

不导出管理站会话、业务 API 或内置 `TemplateExample` / `ResourceWorkflow` 演示流程。项目批准组件列表保留在快照与交付元数据中；共享控件导出范围不是业务权限控制。

## 平台部署者准备代码归档

部署时先构建并保存可执行运行时，再构建前端，之后启动或重启工作区服务：

```sh
npm run delivery:runtime
npm run build
npm start
```

开发环境可在构建归档后启动 `npm run dev`。服务应加载与归档一致的生成标识；修改源码后需要重新构建归档并重启服务。不要在旧服务进程仍加载旧标识时把新归档当作旧版本的实现。

- `artifacts/runtime-builds/<构建指纹>/`：不可变运行时代码、样式、类型、许可及逐文件 SHA-256 清单。
- 数据库目录下 `deliveries/<项目>/<版本>/ready/`：生成的包和不可变交付记录；默认位于 `.workspace/deliveries/`。
- 新包只从目标发布快照和匹配代码归档构造。缺少归档、校验失败、项目关联错误均拒绝生成。
- 已生成包可以在当前源码升级后继续下载；下载前校验归档内容。不会因当前草稿变化自动重打或替换。
- 老历史发布未保存匹配可执行代码时明确不可生成，不把当前代码冒充历史实现。

备份部署环境时，应一并保留工作区数据库、`deliveries` 和 `artifacts/runtime-builds`。项目 JSON 数据备份仍不包含可执行代码归档。

本机部署者也可以使用命令行。该命令需要本机数据库文件访问权限，只读取指定项目的发布快照；团队成员应使用鉴权后的网页入口：

```sh
npm run delivery:project -- --project guokexin --version 2.0.0
# 可选：--database /path/to/workspace.sqlite
```

`2.0.0` 为命令格式示例，必须替换成实际存在的发布版本。命令输出归档路径、版本关联和 SHA-256。缺失版本不会回退到源码默认主题。

## 独立业务参考工程

`consumer-project/` 是单独的 React / Vite 工程，安装项目 tarball，不引用管理站源码。它使用自己的 Node HTTP 接口和本机 JSON 存储，实现查询、编辑、名称校验、修订冲突和持久化；接口数据为参考资源，没有接入公司的业务系统，也不提供生产业务鉴权。

```sh
cd consumer-project
npm install
npm run build
npm test
npm run dev
```

浏览器入口 `http://127.0.0.1:4186/`，业务接口监听 `127.0.0.1:4187`；默认仅本机访问。参考数据位于 `.data/resources.json`，与管理工作区数据库隔离。

验收包位于 `artifacts/project-delivery-acceptance/`，包含国科信 9.0.0、9.1.0 与测试客户 B 9.0.0；这些高版本号仅为隔离验收夹具，不得当作真实客户发布。宿主通过 `expected-release.json` 检查包的项目、版本、运行时和完整快照标识。

包内 `examples/ControlledForm.tsx` 已在参考工程复制为 `ControlledForm.tsx` 并通过类型检查。实际应用应自行实现数据请求和业务权限；组件只接收受控值、回调与反馈。

## 尚需真实项目输入的范围

- 首个公司业务工程、技术栈和接口地址尚未指定；本轮完成独立参考工程验证，不能宣称已接入公司业务系统。
- 私有 npm 仓库、团队 CI 凭据和发布域名未配置；当前交付渠道是有权限的工作区下载。
- Vue/SSR 支持、按需拆包和字体加载优化尚未完成；当前示例包约 5.1 MB。

后续升级必须读取版本差异，验证真实业务页面，再显式更新包和锁文件。回退仅覆盖组件代码与主题；业务数据结构变更由业务工程单独处理。

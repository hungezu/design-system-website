# 表格阴影、按钮白字与项目入口验收

## 表格固定列阴影

共享表格与成员/用户原生表格复用 observeHorizontalOverflow。仅 scrollWidth > clientWidth + 1 时设置横向溢出标记并显示固定列阴影。ResizeObserver、内容变化和字体加载后重新检查；容器放宽时移除阴影。列固定位置与末尾 16px 不变。

浏览器连续验证：宽容器（984px）无溢出、阴影 none；窄容器（400px）中共享表格内容 652px、原生表格内容 740px，均出现阴影；恢复宽容器后均为 none。

## 按钮文字

用户明确要求主要按钮用白字。默认、悬停、按下的实心品牌按钮文字统一白色；不足 4.5:1 时只加深按钮配方底色，品牌主色不改。字号与字体继续遵循所选字体。

真实测试项目：旧 1.0.1 快照保存的是 #457EED 背景、黑字与 PingFang SC。当前草稿实测为 #3F73D9 按钮背景、白字，品牌变量仍为 #457EED，字体仍为 PingFang SC，实测对比度 4.50:1。历史发布不重写。

## 项目标识

项目标识用于网址、权限关系、版本归属，系统仍需保留。创建表单只要求项目名称；自定义标识折叠到可选项。留空时服务端生成唯一 project-xxxxxxxx 标识，已有手动标识与重复校验继续有效。

浏览器仅输入临时名称验证创建按钮启用，随后清空，没有创建用户项目。实际自动生成与权限关系通过隔离数据库接口测试验证。

## 设计检查

前端说明实际能力：无需代码可检查占位文字和品牌按钮文字对比度，粘贴代码可检查可识别的组件/变量引用。中文结果包含通过、提醒、错误与未能验证计数。不会执行输入代码、调用 AI，也不宣称截图/交互/权限检查通过。

历史版本使用该冻结版的组件清单，避免按当前草稿判断旧版；输入或检查上下文改变后旧结果不再展示。真实草稿空代码运行得到 2 项通过，按钮白字 4.50:1、占位文字 4.56:1。

## 验证

763 项前端测试、32 项服务端测试、前后端 TypeScript、修改文件 ESLint 及生产构建通过。构建保留已有大 chunk 提示。交付规范仍读取冻结值；新增表格变量缺失的旧快照不会因新版可选变量被误拒绝。

本次同时修复已存在分层尺寸接入中的 token 分类类型错误，以及 component-gap=initial 时预览间距未回退的问题，保留分层尺寸实现。

最终 `verify:design-md` 通过：两个隔离项目、三个版本的真实组件包可独立安装并编译 Markdown 示例，错误值回调反例被类型检查拒绝。本地后端已重启以加载自动项目标识和新的快照生成逻辑。

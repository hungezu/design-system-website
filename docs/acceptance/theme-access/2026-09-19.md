# 全站主题边界与登录权限自查

## 已确认并修复

1. 平台 --brand-primary 已是 #171717，但成员页主按钮的组件配方和 Runtime 别名仍是 #315C52；下拉弹层也继承旧绿色。根因是只覆盖少数语义值、组件配方在祖先作用域提前解析、Portal 未获得平台完整变量。现在 AppThemeScope 从唯一 app-tokens.css 解析完整主题与别名，所有平台页及登录页共享，并通过 PreviewScope 传递给弹层。项目预览与公共基线分别完整覆盖。
2. 原 Runtime 的高优先级按钮类会覆盖自研 Button 状态颜色。统一由自研配方控制默认、悬停、按下和禁用值，保留危险语义。成员“移除”原先使用不支持的 danger/ghost 组合，已改为已有的危险次按钮。
3. 异步 auth/me 旧响应可能在退出或新登录后重新写回旧会话。增加请求代次与取消保护；账号更换时重新挂载工作内容，退出后清理客户端项目清单。
4. 项目权限变更后页面可能保留旧入口到下一次定时刷新。API 403 现在触发会话/权限重查；服务端仍在每次请求即时检查真实权限。
5. 正常登录也计入同 IP 的 25 次限制，可能导致团队被误锁。成功登录清除其失败计数，失败按 IP 与账号分开累计；连续错误仍受限制。新增 26 次连续成功登录、25 次错误与账号隔离回归。
6. 已登录访问 /login 会落入未找到页面，项目管理员访问平台管理会静默回首页。分别改为进入项目列表和明确显示平台权限不足。
7. 账号菜单在公共页不再把所有非平台管理员称为“查看者”；明确“项目成员 · 权限按项目分配”，项目内显示当前项目角色。管理表单必填内容未完整时禁用提交；网络状态提示避免被固定顶栏遮挡。

## 权限验收

服务端使用隔离 SQLite 和真实 HTTP 请求。覆盖匿名拒绝、查看者不可保存/发布/管理、编辑者可保存不可发布、跨项目拒绝、邀请过期/重放/撤销、最后管理员保护、停用立即失效、密码重置及持久化；同时通过备份与交付包权限测试。

浏览器使用 localhost:5181 的隔离验收服务，与实际 127.0.0.1 的登录会话分开。查看者只见受邀项目，直接访问主题编辑与成员管理均被拦截；项目管理员能进入本项目管理，访问 /users 显示“需要平台管理权限”。退出返回登录，再登录后显示正确项目角色。没有修改实际成员、账号、主题或发布新版本；实际站点的发布弹窗仅打开检查并取消。

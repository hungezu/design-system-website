# 多级表头与 HeroUI Table 组合方式验收

参考：用户提供的四层分组表头截图，以及 https://heroui.com/en/docs/react/components/table （本次读取页面显示 v3.2.6）。

## 已落地

- 保留现有 React Aria / Runtime 与已确认的灰色外层、白色内容区、可配置圆角。参考 HeroUI 的标准/轻量两种表面、独立滚动区和容器内 Footer。
- DSTable 新增递归 columns.children、fixed、align、variant、footer；旧单层调用继续使用原实现，新分组调用使用正式表格语义。
- 多级组标题按叶子列数 colSpan 合并，叶子标题按剩余深度 rowSpan 补齐；正文仅输出叶子列，headers 关联全部祖先。
- 四层示例包含姓名、个人信息 / 年龄 / 居住地址 / 街道 / 楼栋信息 / 楼栋 / 门牌号、公司信息、性别。
- 固定列必须连续位于左右边缘，整组固定或整组滚动；混合固定区与滚动区的组会报告清晰的配置错误。排序仅在叶子列，垂直滚动固定整块表头。
- 标准、轻量、合并分页、多级表头、固定列、选择、空数据、加载均有真实前端示例；现有排序、单元格操作和密度场景保留。
- RuntimeExample、资源管理示例、列表模板改用 footer 同容器分页。分页在表格滚动区之外。
- 总条数左侧额外内缩 8px；分页按钮与每页条数触发器统一 28px，已注册 pagination-control-height 并更新绑定。
- 公共和项目草稿模板增加「多级表头」入口。旧冻结 API 未声明 footer 时不展示新分组入口。
- AI 设计 MD 同步普通合并分页代码、四层分组代码与布局规则；消费验证改为编译文档内全部 TSX 示例。

## 浏览器结果

完整场景：/templates/template-list?variant=grouped-header
组件场景：/components/table?variant=grouped-fixed
分页场景：/components/table?variant=pagination

- 四层表头实测每层约 38px；姓名/性别跨 4 行，年龄及公司叶子列跨 3 行，街道跨 2 行。
- 横向滚动约 219.84px 后，选择列、姓名、性别位置保持不变；8 个叶子表头与对应数据列 X 边界差均为 0px。
- 纵向滚动约 40.48px 后，整块 thead 与滚动容器顶部差为 0px。
- Footer 在滚动容器之外，横向滚动前后 X 位置不变。
- 页码、翻页和容量触发器实测高度约 27.99px；总条数相对分页容器内缩约 8.00px。
- 排序、当前页选择、跨页保留、筛选清空选择、加载禁用、空状态跨列由行为测试覆盖。
